# Developer Guide: `@build_context` Agent

Welcome to the **Context Builder Agent (`@build_context`)**! This agent acts as a specialized repository context ingestion architect. It parses heterogeneous specifications, spreadsheets, schemas, and source code controllers inside a strictly guarded `./ingest/` directory, extracts their semantic structures, and compiles them into a local relational database for downstream test-generation or code-generation tasks.

---

## 🚀 Core Workspace Workflow

Using the agent in your daily development lifecycle follows a simple 3-step loop:

```
Step 1: Move specs/code to ./ingest/
        │
        ▼
Step 2: Save files OR run @build_context /ingest
        │
        ▼
Step 3: Query, Trace, or Visualize the resulting context graph!
```

---

## 🛠️ Slash Commands Reference

Inside the **VS Code Copilot Chat** panel, interact with `@build_context` using these five specialized slash commands:

### 1. Ingesting Files (`/ingest`)
Scans all documents in `./ingest/` and executes the multi-agent refinement pipeline.
* **Prompt**: `@build_context /ingest`
* **Workflow**:
  1. The local python parser reads Word documents, PDFs, Excel grids, Gherkin features, OpenAPI schemas, and TS/Java controllers.
  2. Spawns the sequential refinement chain powered by the **GitHub Copilot SDK (`gpt-5`)**:
     * **`rule_extractor`** extracts policy constraints and pricing surcharge grids.
     * **`tech_mapper`** maps REST API endpoints and data model schemas.
     * **`relationship_linker`** identifies connections between rules and technical components.
  3. Inserts nodes and relationships into the Semantic Context Graph.

### 2. Querying the Semantic Graph (`/query <term>`)
Performs a keyword search on nodes in the graph store directly from the chat.
* **Prompt**: `@build_context /query age`
* **Expected Output**: A beautifully structured Markdown table listing matching entities:
  | Node ID | Entity Type | Entity Name | Description |
  | :--- | :--- | :--- | :--- |
  | `rule_age_limit` | `business_rule` | Driver Age Limit Eligibility | Age must be >= 18 and <= 75... |

### 3. walking Traceability Paths (`/trace <node_id>`)
Walks forward and backward relationships in the graph store to resolve dependencies for any given node.
* **Prompt**: `@build_context /trace rule_age_limit`
* **Expected Output**: A nested bullet tree showing the logical connections:
  * 🟨 **[BUSINESS_RULE]** `rule_age_limit`
    * ➡️ *TESTED BY* 🟥 **[TEST_SCENARIO]** `scenario_applicant_under_age`
    * ➡️ *IMPLEMENTED BY* 🟦 **[API_ENDPOINT]** `POST /api/v1/quotes/premium`
      * ➡️ *CONTAINED IN* ⬜ **[CODE_COMPONENT]** `QuoteController`

### 4. Database Sync Status Check (`/status`)
Validates that the graph store is in sync with the filesystem by comparing file checksums.
* **Prompt**: `@build_context /status`
* **Expected Output**: A status report showing if any local file in `./ingest/` was modified or deleted since the last ingestion run.

### 5. Interactive Network Graph Panel (`/view`)
Launches a stunning interactive graph canvas in a custom VS Code Webview panel.
* **Prompt**: `@build_context /view`
* **Expected Output**: A futuristic dark slate Webview panel displays.

## 🎨 Immersive Interactive Graph Visualization

When you run `/view`, the agent fetches the entire relational graph from the graph store and opens a premium, hardware-accelerated **Interactive Network Viewer** inside VS Code:

* **Futuristic Slate Canvas**: Deep dark theme (`#0f172a` slate base) with smooth Bezier-curve relationships.
* **Color-Coded Entities**:
  * 🟨 **Golden Yellow**: Business Rules (surcharges, tables).
  * 🟩 **Emerald Green**: Product Features.
  * 🟦 **Indigo Blue**: REST API Endpoints.
  * 🟪 **Creative Purple**: Payload Data Models.
  * ⬜ **Light Gray**: TS/Java Code Classes.
  * 🟥 **Coral Red**: BDD Test Scenarios.
* **Interactive Controls**: You can fluidly pan, zoom with your mouse wheel, and click nodes.
* **Side drawer Inspector**: Clicking any node slides open a rich detail panel displaying its Sanitized ID, entity type, detailed description, and raw JSON metadata inputs.

## ⚡ Background Watcher Hook (`on-save`)

You do not even need to run `/ingest` manually every time! 

The system installs an event-driven file watcher hook inside `.github/hooks/on-save.json`. Whenever you edit and save any document inside your `./ingest/` folder (such as adjusting an age surcharge threshold in an Excel sheet), the extension **instantly triggers the full Copilot SDK LLM pipeline** in the background. A silent notification will confirm: `Silent sync completed. Context graph refreshed.`

---

## 🤖 Downstream Agent Integration (Downstream API)

The graph store (`graph.json` and `documents.json`) generated by `@build_context` resides in a `.context_builder/` directory at your project root. Because these files contain a normalized semantic graph, other agents (like a `@test_creator` or `@code_generator`) can leverage this data connecting to the graph store or using MCP. 

This prevents large, bloat-prone context windows during long conversations and ensures your other AI tasks are fed with highly structured, accurate data.
