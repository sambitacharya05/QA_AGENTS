# Test Case Creator - Technical Specification

## Overview
The **Test Case Creator Agent** is a state-of-the-art dual-agent system designed to ingest semantic context graphs (such as those generated by the Context Builder), plan, draft, verify, and export highly compliant test cases. 

It acts as a downstream consumer of the Semantic Context Graph, specifically focused on translating business rules and their traced implementations into structured test coverage, which can be directly exported to Azure DevOps (CSV format) alongside comprehensive markdown coverage reports.

## Architecture & Technology Stack
The system employs a decoupled, dual-language modular architecture:

1. **VS Code Frontend Extension (TypeScript)**:
   - Built as a standard `@create_tests` chat participant and command orchestrator.
   - Responsible for module analyses, generating scenario proposals (Maker), stepping through generators, and executing Verifier loop checks.
   - Utilizes `Zod` for schema validation and houses the core LLM agent prompts.
   
2. **FastMCP Execution Engine (Python)**:
   - A local tool execution layer running as an MCP server (`mcp_server.py`).
   - Handles heavy computational lifting: parsing large context graphs, executing BFS subgraph slicing, and data formatting.
   - **CSV Serialization**: Implements strictly compliant RFC 4180 Excel CSV formatting tailored for Azure DevOps ingestion (`csv_writer.py`).
   - **Validation**: Ensures structural integrity of the ingested context graphs (`graph_validator.py`).

## Directory Structure
- `vscode-extension/`: TS source code, configurations, Zod schemas, package dependencies (`package.json`), and agent prompts.
- `engine/`: Python backend exposing FastMCP server tools.
- `tests/`: Extension integration and Python unit test suites (using `pytest`).
- `specs/`: Project design documentation and prioritized implementation indices.

## Core FastMCP Tools (Python Engine)
The Python backend exposes several critical tools to the TS frontend via the MCP standard:

- `validate_graph(graph_path)`: 
  - Validates the structural integrity of a `graph.json` file.
  - Ensures correct JSON format, presence of `business_rule` nodes, valid edge mappings, and returns blocking errors vs. warnings.

- `extract_subgraph(graph_path, rule_ids, bidirectional)`: 
  - Extracts the minimal connected subgraph reachable from specified business rules.
  - Utilizes bidirectional BFS traversal across specific relationship types (`TESTS`, `IMPLEMENTS`, `CALLS`, `TRACES_TO`, etc.) to pull in related code components, existing tests, and API endpoints without overwhelming the LLM context window.

- `write_azure_csv(test_cases_json, output_path, area_path)`: 
  - Deserializes generated test cases from the TS agent and serializes them into Azure DevOps-compliant CSV rows.

- `write_coverage_report(markdown_content, output_path)`: 
  - Persists the final comprehensive markdown traceability and coverage report to the disk.

## Workflow Integration
1. The **Context Builder** (or similar tool) generates a semantic graph of the workspace (`graph.json`).
2. The **Test Case Creator TS Extension** receives a user prompt (e.g., via `@create_tests`).
3. The TS Extension delegates graph traversal to the **Python MCP Engine** (`extract_subgraph`), fetching only the required rule nodes and their dependencies.
4. The TS Extension invokes an LLM to draft test scenarios based on the extracted subgraph.
5. A verification loop checks the drafted tests against the original context rules.
6. Once verified, the TS Extension utilizes the Python Engine to generate an Azure DevOps CSV and a Markdown coverage report.

## Autonomous Agents (.agent.md)
The Test Case Creator pipeline is driven by a suite of specialized LLM subagents, each handling a distinct phase of the test generation lifecycle:
1. **Module Analyzer (`module_analyzer.agent.md`)**: Acts as a semantic routing agent. It classifies user queries against the business rule index and returns a JSON object identifying matched rule IDs or determining if the query targets all modules.
2. **Test Case Analyst / Maker-1 (`test_case_analyst.agent.md`)**: The QA Scenario Designer. It executes a rigorous 6-phase analysis chain (Rule Pre-Classification, Attribute Identification, Equivalence Class Table, Happy Path Design, Linear Expansion Matrix, and boundary/RBAC augmentation) to propose structured test scenarios.
3. **Test Generator / Maker-2 (`test_generator.agent.md`)**: Produces concrete, numbered, step-by-step manual test cases based on confirmed test scenario categories. It strictly enforces rules like the "Step 1 Precondition Invariant".
4. **Test Verifier / Checker (`test_verifier.agent.md`)**: An independent auditor that checks generated test cases against a 7-point quality rubric (verifying Happy Path coverage, Linear Expansion Matrix completeness, logical flow, business rule traceability, EP/BVA coverage, and CSV compliance). It outputs a structured Gap Log to drive correction loops.
5. **Coverage Reporter / Compiler (`coverage_reporter.agent.md`)**: Generates a premium Markdown report documenting requirement compliance percentages, condition coverage metrics, end-to-end traceability matrices, gap analysis, and the verification loop history.
